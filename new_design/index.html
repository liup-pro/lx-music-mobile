EchoIsle · 五个 Tab

移动端 UI 原型（HTML/CSS/JS）：首页 / 歌单 / 排行榜 / 我的 / 设定，左上角可切手机竖屏、手机横屏与Pad 横屏三种外形，另有一档明暗主题。信息架构不是照搬竞品，而是由音源脚本解码出的能力边界反推出来的——音源只能把一首歌变成能播的声音，其余内容全部来自平台曲库。

音源能力 → 设计约束

解码结论UI 落点
仅注册 musicUrl 事件，其它 action 抛错推荐、榜单、歌单、歌词、评论一律按「平台曲库内容」呈现，原型里为 mock；音源只在点播放那一刻介入
getId 分支：tx / wy / kw / kg / mg音源面板内的平台单选组 + 每首歌的来源角标；列表里给「暂不能播」的降级态，而不是报错
各平台 ID 取值不同（kg 用 hash，mg 用 songmid+'d'）不暴露给用户。取哪个字段、拼什么串是脚本的事，界面上只留「这个来源能不能播」
没有 getPlaylistUrls，歌单号不能直接换成内容页头「打开歌单」收的是用户自己从平台分享出来的那串号，只当「去哪份歌单」的坐标；打开之后仍然逐首判能不能播
s = "xx|128k&..." 全平台仅 128k音质选择器只在音源声明多档时才出现可选项，野花下只读 + 一句说明；不做假 HQ 开关
脚本可多份共存、单选生效（LX 音源模型）面板顶部「已安装音源」列表，切换后平台覆盖范围、音质档位与三个 Tab 的「可播」数字同时刷新
初始化拉取 /urlinfo/ 返回 u、h只保留右上状态灯；「检查更新」撤掉——不连真实接口的更新按钮是假按钮，设定页里也不放
请求带 md5 签名、跨域受限原型不真连接口；签名与取址模板完全不出现在界面上

文案的取舍

用户不会关心 /url/{source}/{id}/{quality}、请求方法、签名、musicUrl 事件名，也不会关心酷狗为什么要用 hash。这些在早期版本里散落在 toast、面板副标题和歌曲行尾部，现在全部撤掉，换成一句人话：能不能播、换一个音源试试。能力推理的过程保留在本文档，不进手机屏幕。

  • 歌曲行的「⋯」原本弹出取址模板，现在弹收藏 / 下一曲播放 / 加入歌单
  • 音源面板副标题从「仅注册 musicUrl 事件」改为「音源只负责把歌曲变成能播的声音」
  • 不支持的来源不显示错误码，显示「暂不能播」并把行压暗，播放时直接跳过
  • 唯一的例外是歌单 ID：分享链接末尾那串数字本来就是用户会互相转发的东西，所以「打开歌单」面板可以直接把它当输入；被藏起来的是各平台 ID 的字段类型与取址方式，data.js 里仍留着 idKey / idExample 供解码

视觉

主色是粉紫渐变 #FF5C8A → #7A3BFF（早期「野花」时期定盘，定名 EchoIsle 后沿用），中性底 #08080C；层级靠 表面色 + 1px 高光描边 + 模糊 而非投影堆叠，接近 iOS 26 的 Liquid 质感。圆角 20/26 双档，字阶 11/13/16/22。状态栏与灵动岛是硬件层，z-index:86 高于推入页(66)/播放页(70)/浮层(80)，只有 toast 在它上面。明亮主题不是另画一套配色，而是在 .phone.light 上重写同一批 CSS 变量，所有组件自动换肤。真正要小心的是半透明叠色：深色底靠「往上叠白」抬亮层级，浅底上同一手法会整片消失——所以 :root 里有一组专门给叠色用的 token，组件只引用它们，浅色层把「叠白」换成「叠黑」，同透明度只反相： --fill-1/2/3/4（行按下的瞬时底 / 控件底 / 按压加重 / 结构件底）、--hairline 与 --hairline-strong（两档 inset 描边）、--glass + --glass-ink（浮在封面图上的毛玻璃贴片及其文字，迷你条 / LRC 浮窗 / 「建设中」角标共用一套）、--danger-ink（报错字：浅底上亮珊瑚读不出来，换深红）。 分组容器（设定列表 / 统计条 / 歌词卡）单独用 --card：深色是叠白，浅色不压黑，而是换成实心白面——页面灰、卡片白，跟 iOS 分组列表一致。 吸顶栏（顶栏 / 分类条 / 底栏）与歌词上下渐隐改用 color-mix(in srgb,var(--bg) …%,transparent) 跟随底色，深浅两档都自动正确，不再需要覆盖层。 留在 .phone.light 里的只有两条改不动的真差异：歌词当前行的投影浓度、浮层遮罩浓度。 压在图上的文字（轮播标题、榜单卡榜名、角标白字）不参与反相——它们的底永远是那张饱和渐变的插画，所以直接锁白；.phone.light 上的 color 仍要重写一次，否则 body 继承下来的字色还是暗色那套。

图标体系

全站图形只出自一处 sprite（<symbol>，共 36 枚），一律 24×24 网格、圆头圆角、只描边不铺面，颜色全部 currentColor——图标本身不带颜色，换肤与选中态都靠继承。三条规则支撑「像产品」的观感：

  • 线宽只有两档：主描边 2.0；显示尺寸小到 16px 以下、或大到 26px 以上的控制键（上一曲 / 下一曲 / 关闭 / 返回 / 加号）提到 2.2 做视觉补偿。同一枚图标里不同线宽不超过两种，再浅的层级用 opacity 表达而不是继续调细线——所以「顺序播放」的斜线压 2.2、母环 2.0 加 55% 透明度，而不是三档线宽各自为政
  • 状态成对出现，只换图形不换尺寸：定时与 LRC 浮窗的开启态是「同一轮廓 + 同色 25% 内填充」，关闭态是纯描边，两枚 symbol 的路径起点与尺寸逐点对齐，切换时只改 <use href>，不加底色、不加角标、不放大
  • 语义写进 aria-label：纯图标按钮（播放页工具行四颗、迷你条三颗）的当前状态只能从图形读，所以状态文案放在 aria-label 上随状态更新（如「循环模式 · 单曲循环」「定时停止播放 · 剩余 12:30」），屏内不塞文字
  • 状态栏的信号 / 电量是硬件层图形，视角与线宽都不同，不参与这套规范；i-clock 是早期定时入口的遗留 symbol，已无人引用，留在 sprite 里不删（后续做「稍后播放」可能用得上）

歌曲行（各页共用）

同一行组件在首页、搜索、歌单详情、榜单详情、最近播放里复用，只有 compact 一档尺寸差异。第二行的字段顺序是固定的：来源平台角标 → 音质标签 → 歌手 → 专辑，中间用 1px 竖线分隔。

  • 顺序按「这条信息有多大局」排：平台与音质是这首歌能不能播的判据，用户扫一眼是为了决定要不要点；歌手与专辑是内容描述，属于补充。所以判据在前、描述在后，与主流 App（网易云 / QQ音乐）把来源与音质放行尾不同，是因为本项目是多平台聚合、音质还会随音源变化，这两个信息在决策上更靠前
  • 压缩时按「专辑 → 歌手」的顺序让步：两枚角标不参与压缩（flex:none），专辑 flex:0 100 auto 先被截断，歌手 flex:0 1 auto 后截断，任何宽度下都能看到平台与音质
  • 落到 RN 时改的是 SongRow 的 subRow 子节点顺序（现为 SrcBadge → subtitle → QTag）：拆成 SrcBadge → QTag → artist → album 四段，subtitle 这一个 prop 要拆成 artist / album 两个，容器上补一条分隔线样式即可，其余 props 与交互不变

三种外形

同一套 DOM，不复制页面：左上角「设备外形」三档——手机竖屏 390×844、手机横屏 844×390、Pad 横屏 1180×820。切到 Pad 时给外框和 body 各加一个 .pad 类，靠一段覆盖样式把「底部 Tab」翻成「左侧导航」；手机横屏只加 .land，把外框转成宽扁形、底栏保持横向、内容区改两列，不引入侧栏。预览窗口不够宽时整体等比缩小（fitFrame() 按 stage 宽度和窗口高度取较小值，手机模式不参与缩放），量到的坐标都还是逻辑像素。

  • 让位用一个变量做完：--nav-w 手机 0px、Pad 236px，顶栏 / 滚动区 / 推入页 / 播放页 / 迷你条的 left 全部引用它——所以手机侧的计算式原样退化成 0，不需要第二套定位
  • 侧栏由原 #tabbar 变身（flex-direction:column + 42px 行高），补了品牌行、「浏览」分组标题、独立的设定入口，底部 margin-top:auto 钉住当前音源状态：脚本名 + 版本 + 平台数 + 音质，解码失败时小圆点变橙。手机模式这四个新节点 display:none，不占空间
  • 内容区加宽不等于放大：轮播 860×216、歌单 / 榜单 4 列、电台 3 列、歌曲行 860 宽，左右各留 30px 边距；.viewport 的 padding-top 同步改成 94px 与 Pad 顶栏等高，胶囊吸顶仍然是 top:0
  • 歌单详情改成 iPad 那种主从布局：左列 318px 放封面（正方向撑满）+ 标题 / 标签 + 播放全部，右列曲目列表自己滚（overflow:hidden + 内层 max-height:100%），滚动条藏在卡内，标题不再被长列表顶出屏幕
  • 播放页开歌词时左右分栏（封面 440 ｜ 歌词 372），转盘留在原地继续转；不开歌词仍是竖排。定时 / 评论 / 音源 这些 sheet 从底部弹出改为居中模态（660px，最大高 74%），拖动条隐藏，出现动画换成 scale + fade
  • 设定页分组两列排布；「我的」的统计条限宽 620px，不被拉到整页宽显得空洞
  • 三档外形切换一律收回浮层与推入页并清掉浮窗的手拖坐标（内联像素是上一个外框的），避免带着旧几何进新布局；toast、LRC 浮窗的位置都按 --nav-w 重算，浮窗拖拽还把屏幕像素除回逻辑像素（frameZoom()）
  • 状态栏保留（时间 / 信号 / 电量）但去掉灵动岛，Pad 外框没有挖孔
  • 「屏幕方向 / 设备外形」是查看器的控件、不属于 App，此前放在手机壳上方，页面一滚就看不见，等于「没有这个功能」。现在它是 position:sticky 常驻条，始终贴在浏览器顶部，深色毛玻璃底与手机外壳分开一层；窗口窄到 860px 以下（裸机预览档）时它压成一条 42px 的窄条、手机高度改 calc(100vh - 42px)，保证切换开关永远露在可视区里

首页

  • 搜索框 → 整页搜索（见下一节）；右上波纹图标 → 音源设置面板（切音源 / 切平台 / 切音质）
  • 那颗波纹图标上的琥珀色呼吸点只有一种含义：当前脚本没配好（未初始化 / 平台对接不上），进来处理一下。配好即整颗撤掉——不给「一切正常」留常驻绿灯，否则用户会把它读成「在线状态」，而这种装饰性常驻点正是最容易被当成假数据的地方（renderNav() 里 #castDot.hidden = state === 'ready'）
  • 轮播三条不是营销位，是三条当前状态：在看哪个平台曲库、正在放哪首、电台还没做。renderBanners() 每次播放与切源后重画，定时器只起一次，不会叠出重复条
  • 榜单 chips 用真榜名（当前平台的homeBoards()，取前 4 张），只驱动下方「热门单曲」；榜里的歌按那张榜所属平台取址，切到没接的平台就明说「这个榜暂时打不开」
  • 「播放全部 N 首」不带平台名：N 已经是按当前音源筛过的可播数，再缀一个来源只会让句子更长
  • 继续收听一行末尾是清空记录（与设定页那行共用 clearRecent()），一行没有就整块连入口一起收掉，不留点了没反应的按钮
  • 每日推荐的首数按这次真正挑到的算（池子 = 听过 ∪ 我喜欢 去重取前 10），池子空就写「先听几首，这里会自动排好」而不是硬编 10 首
  • 热门歌手没有主页可去：点头像 = 播当前这张榜里他/她的歌，对不上就明说；下面补一行灰字讲清头像是示意插画，平台没给歌手照片
  • 热门单曲行去掉「⋯」：这一列的定位就是单击即播，收藏与加入歌单留给播放页和详情页
  • 电台（随手听两张卡 + 快捷入口 + 轮播里那条）统一标 建设中：卡片右上角挂角标，点击只给「电台 · 还在建设中」，不假装能播直播流
  • 任意歌曲行 → 迷你播放条（喜欢 / 播停 / 下一曲三颗）→ 点开播放页

搜索

音源没有 search 事件，所以搜索是「平台曲库」能力，原型里在本地对 mock 曲库做匹配。原来点热词只弹一句占位 toast，现在是一整页：没输入时是历史 + 热搜，回车或点词才发搜索（真实侧一次搜索要同时打单曲和歌单两个接口），中间亮一句「正在搜索…」，结果回来才铺列表。

  • 整页推入（.pl-layer 右滑），头部是搜索框 + 取消，padding-top:54px 与首页顶栏的搜索条对齐，吸顶分段条在滚动容器内容盒上 top:0
  • 结果 单曲 / 歌单 两类分开，标签上直接带命中数；默认落在单曲，若单曲零命中而歌单有则自动切过去，反之亦然
  • 单曲复用 songRow：来源角标、音质、时长、可播状态与首页一致，点行只入队播放并留在搜索页继续挑；底部一句「N 首 · 其中 M 首现在这个音源能播」
  • 歌单复用 plCard 与详情层，所以 #searchLayer 在 DOM 里排在 #plLayer 之前，同 z-index 下详情层压在搜索结果之上
  • 匹配按词拆：「lofi 学习」整串谁都命中不了，拆成两个词后命中带「学习」标签的歌单；范围含歌名 / 歌手 / 专辑 / 平台名（搜「咪咕音乐」出的是咪咕那几首）；历史词去重最多留 8 个，可一键清空
  • 换词时自动落到有结果的那一类，但用户手动点过的标签不会被抢走；只有一类为空时给「看 N 份歌单 / N 首单曲」的跳转，两类都空才说没找到，并给换词建议
  • 输入里带「音源 / 平台」时追加一个「去设定里看音源」的入口，把搜不到的东西指回它该在的地方
  • 热搜是真实接口数据，屏上截前 10 条；一条都没取回来时写「热搜暂时载入失败 · 直接输入关键词搜索」，不留一片空白让人以为页面坏了
  • 播放状态变化时 syncLists() 会连搜索结果一起重画并保住 scrollTop，不会出现播完一首列表跳回顶部

歌单

歌单目录来自平台曲库，音源给不了任何 playlist 事件，所以这一页只做「浏览 + 判断能不能播」：分类 chips 横向滚动、我的歌单前置、推荐池按分类过滤后给出每份歌单的 N/N 首可播，页头留给「按 ID 打开别处分享出来的歌单」。

  • 分类首位是「全部」并默认选中：不让用户进场就先替他被预设一种口味。分类目录逐平台不同（真实侧是 getTags(source)），chip 行只放得下「全部 + 该平台热门」，行尾一枚「全部分类」开 #plTagsSheet 看全量分组，取不到时写「这个平台暂时没找到分类」；切平台会把选中的分类退回「全部」，上一家的分类在这一家目录里可能根本不存在
  • 分类标签与歌单是多对多（一首歌可挂多个 cats）；分类下确实没有推荐时给空态「这个分类下暂时没有推荐 · 换一个分类试试」，不硬凑内容
  • 推荐池也是上滑加载更多：一次只铺 10 份（真实侧歌单列表同样是一页一页来），滚到列表底部自动取下一批，载入中一行是转圈 +「正在载入下一批…」；某一批失败时这一行变成「这一批没有载入 · 点击重试」的可点重试，重试即成功。原型里第 3 批故意先失败一次，好让这条真实路径看得见。计数在没取完前写「已列出 N / M 个」，取完收敛成总数并把列表尾收上「没有更多了」——不是原来那种「一屏铺满就没了」的静态 30 条。切平台或换分类会把已铺的批次重置回第一批（renderPlaylistPage 对比 plCat / activeSource）
  • chips 吸顶用 top:0 而不是 top:110px——sticky 的参照系是滚动容器的内容盒，而 .viewport 已经有 padding-top，再加偏移就会在顶栏下面留出空隙；padding-top 也从 112 收到 110 与顶栏同高，条内上内边距 3px，实测吸住后胶囊离顶栏下沿只有 3px
  • 「我的歌单」这一排现在是真数据：详情层右上角那颗删除钮删掉的单子会立刻从这排消失，删空了给「还没有自建歌单 · 听到喜欢的先收藏进来」，不留一个空横滚条
  • 页头的 + 换成「打开歌单」按钮：主流 App 都在这一页给用户一个「我手上有链接」的入口，#plIdSheet 收两种输入——整条分享链接（按域名认平台）或只有那串号；只填号时必须先点这份单子来自哪个平台，真实侧 getListDetail(id, source, page) 少了坐标就取不到歌，所以提示语写「仅凭一串 ID 判断不了来源」
  • 面板里预置 4 个「平台简称 + 那串号」样例胶囊，点一下就填好并直接打开；空输入、没选平台、链接不是这五家的、号形不对，各给一句人话错误，错误行在开始重新打字时自动收起
  • 打开之后仍走同一个详情层，toast 只说「已去某平台打开这份歌单 · 里面的歌要现从平台取」：此刻一首都没取回来，报 N/N 首现在能播 就是编数
  • 详情层从右侧推入并覆盖 Tab 栏，用 translateX + visibility 延时，和浮层的上滑手势在方向上区分开
  • 顶部毛玻璃取当前封面主色，整页只保留一次「播放全部 / 随机播放」，其余操作收进歌曲行的「⋯」
  • 曲目是分页取的（真实侧 getListMusics(id, source, page) 一页一页来）：进来看见第一批，滚到底自动取下一批，载入中一行是转圈 +「正在载入下一批…」；这一批没取到时换成「这一批没有载入 · 点击重试」，点一下接着取。原型里第 3 页故意先失败一次，好让这一行看得见（重试即成功）。整单列完时列表尾补一行「没有更多了」——一屏内就列完的短单子（比如 5 首的自建歌单）也一样有，滑到底不至于对着空白猜还在不在加载
  • 切音源后详情层不关闭，syncPlLayer() 原地重画已经取到的每一行的可播状态，已取到的页数不丢

排行榜

音源没有 rank 事件，但「某个平台的第几名」是平台曲库自带的信息，所以这一页改成按平台组织：当前音源接了哪些平台，就只列这些平台的榜，不做「混了五个平台再逐首标能不能播」那种列表。

  • BOARDS × 五个平台 = RANK_CHARTS（每家 9 张榜，共 45 张）：平台给的榜单目录全列，当前平台的 9 张整体排在最前，其余按平台分组接在后面——原来每人只截 6 张，被砍掉的三张在界面上完全没有解释，用户只会以为「这个平台就这几个榜」，现在不再截断。首页那排 chips 仍然只取当前平台的前 4 张，受音源约束
  • 45 张卡一屏放不下，所以按平台分段（rankGroupHead()：平台名 + 「N 个榜 · 热歌 / 新歌 / 飙升在前」）并在段内按「主打榜优先」排序：中途接着往下滚的人也能知道自己正站在哪家的曲库里，不至于把五家的榜看成一锅粥
  • 分段之上同样分批铺：一次 8 张，滚到底自动取下一批，底部状态行与歌单页、详情层共用同一套语义（转圈 + 载入中 / 这一批没有载入 · 点击重试 / 没有更多了）；45 张全列完后以「没有更多了」收尾；切音源会把分组与已铺批次一起重置，当前平台回到最前
  • 封面按「榜名」定色、按「榜型」定形（CHART_TINT / CHART_EMBLEM）：每张榜一个强调色 + 一层同色相平色深底（强调色压暗 76%，shadeHex）——热歌 = 黑胶，新歌 = 音符，原创 = 麦克风，飙升 = 上升箭头，古典 = 留声机，电音 = 方波，符号都按 512×512 画、居中留白。原来色只按六种榜型给，45 张里 29 张回落成同一个「橙黑胶」，一段里几张榜只有名字不同——现在同名榜跨平台保持同色（五个平台的欧美榜是一张脸，同榜就该同脸），段内相邻榜色相都拉开。榜单封套是资产、平台只是来源归属——若按平台上色，五站同榜型会撞成一张脸，用户分不清点的是哪个榜
  • 徽标是自绘单色线条 SVG：512×512 画布上居中一枚一笔画符号（圆头圆角），符号色与底色随榜名成对出现（底 = 色压暗），不放光晕、网点、阴影——榜名白字 + 深色字影直接压上深底；卡上与详情头图共用同一份矢量缩放，不糊。以后加榜照同一配方：一个符号 + 一个强调色，深底由它压暗得出
  • 2 列方块卡片：榜名左下角 900 字重，底边一行小字给平台全称。「每小时更新」那枚角标和「N 首」那行撤了——更新节奏接口没给，写上去就是编的，榜有多长也不是用户在这一格要看的
  • 同一套封面在详情层头图复用（chartArt() 与 rankCard() 共用该榜的色与符号），从网格点进去认的还是同一张脸；榜单详情不再落到通用随机封面
  • 点卡片进入详情层，与歌单共用同一个页面：openPlaylist(chart, 'rank') 靠 kind 换面包屑、行动按钮文案与页脚说明
  • 整榜都按该平台取址，进来就是一整份能播的排名——所以「N/M 首能播」提示条、来源 chip 与跨平台圆点对照块全部撤掉
  • 来源筛选只剩设定页与音源面板一处，切换后 renderRankPage() 随 repaintAll() 重画网格

我的

只留本地状态：收藏、播放记录、自建歌单。主题、缓存、播放偏好这些开关从这一页撤走，右上的齿轮进的是独立设定页。

  • 统计条只留本地能算准的三项（喜欢 / 歌单 / 最近播放）——「可播来源」是音源的能力，不是我的内容，挪到设定页的「接入的平台」去讲
  • 右上入口是设定（齿轮）：#i-gear 重画成外圈 + 内孔 + 八颗齿轮牙，原来那版只有中心圆加几根射线，看着像亮度调节
  • 「我喜欢」卡片直接播放收藏里当前音源能解析的第一首，放不出的会被跳过
  • 「我的歌单」标题右侧那角是新建歌单：原型旧版写的是「去歌单页」，跳过去只是换个 Tab，给不了用户想要的动作。#createSheet 起个名字就能建，规则与旧屏一致——空名不建、超 100 字截断、同名先问一句「已经有一份同名歌单了，还要继续建吗？」，按钮在落库期间亮「创建中」
  • 本地自建歌单（含新建的、收藏、试听）在详情层是本地形态：右上角那颗不是心钮而是删除钮，按下必过二次确认，说清掉的是这张单子和它列出的歌目记录，歌本身的文件不动
  • 播放记录由 state.history 去重累积；清空后标题右侧的「清空记录」随空态一起隐藏，不给一个点了没反应的按钮
  • 「⋯」里的加入歌单会立刻反映到本页与【歌单】页的曲目数；反馈句不带计数（真实侧计数在异步写库之后才更新，按下那一瞬报出来的数不可信）
  • 页头副行是「没有账号 · 收听都记在这台设备上」：原来那行「听众 ID 8842 0613」是编的，本项目没有用户 ID 概念

设定

推入式整页（复用 .pl-layer 的右滑与毛玻璃），先落三组：外观 / 数据与缓存 / 关于。原则是「一个开关只在它的现场出现一次」——音质与内容平台在音源浮层、循环与定时在播放页工具行，设定页再列一遍就会出「两处显示不一致」。

  • 外观三档（明亮 / 黑暗 / 跟随系统）用行内选中态与「在用」回显，不需要用户记住自己在哪开过；「跟随系统」在浏览器里就是 prefers-color-scheme，与手机上同构
  • 出厂默认是「明亮」：主流音乐 App 的默认外观几乎都是浅色（首次打开要能读懂界面，而不是先撞上一块黑屏），本项目多数使用场景是白天；深色留给用户主动选，或选「跟随系统」交给手机决定。默认值写在 state.theme 与 localStorage 兜底两处，清掉本地存储后回到浅色
  • 「关于」组把出处写在明面上：只留一行——左上品牌名，副行「内核由 lx-music-mobile 原作者与社区维护」（取数、音源与播放内核全部来自该开源项目，Apache-2.0），右侧版本号 APP_VERSION = 1.9.1 沿用其 package.json，不为界面重写另起。尊重作者、也让读者一眼知道上游是谁
  • 「数据与缓存」明确只影响本机：清除播放缓存不动收藏、歌单与播放记录，清空记录那一行右侧就是当前条数
  • 删本机数据前一律走同一个二次确认层（清除缓存 / 删除歌单 / 同名建单共用）
  • 主题 / 播放模式 / 昵称 / 音源脚本 / 内容平台 / 音质这六项写 localStorage（键 echoisle.proto.v1）：真实侧它们各有 setting 键，刷新一次就回到默认等于骗人。队列与播放记录不写——那是听歌过程数据，每次打开重排一遍才看得清各形态
  • 播放页工具行改成纯图标后，设定页不再重复挂循环/定时的开关：这两项的当前值在播放页的图标与 aria-label 上，重复一份文字版只会在两处对不上

正在播放页

控件按「主传输 / 次级工具」两层排布：主传输行只留上一曲 / 播放 / 下一曲三颗，定时从这一行挪进下面的工具行；播放队列入口按需求去掉，改由 LRC 浮窗承担跨页面常驻的角色。

  • 底部工具行四颗（定时 / 循环 / 浮窗 / 评论）没有文字、没有选中底色：按下去只换图标，说明交给 aria-label 与 toast。开启态统一用「描边 + 同色低透明度内填充」表达（时计盘面、浮窗气泡各充一层色），一处语言全站通用，不再给按钮铺一块高亮底
  • 进度条 pointerdown/move 拖动即定位，拖动期间关掉 transition，松手才回写 state.t 与歌词锚点
  • 上一曲 / 下一曲在当前队列内跳转，并自动跳过本音源解析不了的来源（切到「落歌」后咪咕、酷狗会被跳过）
  • 循环模式五态轮转：列表循环 → 随机 → 顺序播放 → 单曲循环 → 播完即停 → 回到列表循环。工具行只剩图形以后，三态不能再共用一枚 i-repeat，所以五态配五个轮廓：双箭头环 = 列表循环、环上压斜线 = 顺序播放（循环已关闭）、环中带 1 = 单曲循环、交叉箭头 = 随机、箭头抵端线 = 播完即停（顺序播放放到头就停、播完即停放完当前这首就停，两句 toast 分开说）
  • 定时停止播放：选档后按钮换成带填充的那枚时计图标，分秒倒计时写进 aria-label，并由 tick() 每秒回写进定时面板自己的副标题。图标后面不塞数字——那等于把刚撤掉的文字状态请回来；到点是停下还是继续，由「听完当前这首」那个开关决定，不是只会暂停
  • 均衡器整块撤掉：音源只注册了 musicUrl，播放内核没有频段增益通道，六段 ±10dB 拖了也不会改变声音，那是假能力
  • 歌词与封面是同一个舞台的左右两页，只由横滑交替：右滑进歌词、左滑回封面（判据与 newui 的 PlayerStageSwipe 一致，|dx| ≥ 24 且 |dx| ≥ |dy|×1.5，纵向一律让给歌词自己的滚动），播放页里没有任何一颗「歌词」按钮。舞台下方留两枚指示点，是这一处手势唯一的可见提示，当前页拉长成胶囊，用 currentColor + 透明度上色，浅色主题不用另写一套底色。音源无 lyric 事件，文案为原型占位（非任何真实歌曲的歌词），屏内只写「歌词由各平台提供」
  • Pad 与手机横屏的歌词态是「唱片 + 歌词同屏」的分栏，滑动只开合歌词栏，不存在翻页，所以指示点在这两种外形里藏掉
  • LRC 浮窗：可拖动的歌词气泡，浮在首页/各 Tab 之上并跟随进度换行，点它回到播放页；全屏播放页打开时自动让位
  • 收藏 / 评论：收藏落在本地 Set 并同步迷你条；评论按页翻（第 1 页也是一次取数，先亮「评论在取了」），回复是嵌套树，逐层缩进带线程竖线，第 2 级起加「回复 @某人」浅色前缀；工具行那颗评论图标不带条数（真实侧此刻还没取到数），面板里那句「其中 N 条乐评人长评」也撤了——接口没这个口径，那个数是拿总数除出来的。浮层滚动只给评论列表这一段：标题、说明、那行「总数 + 热度排序」和拖动条一起钉住不动，滚到底翻下一页的判据也换到列表自身上，滑多了标题与总数不会被顶出视野
